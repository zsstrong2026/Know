# PM PRD 生成（pm-prd-generator）

**确定性技能**：给定结构化上下文即静默产出双产物，不向用户提问。
服务于「PM 工作站 → 版本管理 → 生成/重新生成 PRD」。

## 1. 触发场景

- 版本状态为 `规划中`，用户点击「生成 PRD」。
- 评审驳回后，用户点击「重新生成」并传入评审意见（产出 PRD-v2、v3…）。

## 2. 输入契约

调用方注入的上下文包含（缺项按括号内规则处理）：

| 字段 | 说明 |
|---|---|
| `version` | 版本号（可为空，定稿后才锁定 `X.Y.Z`）、计划上线日、生成轮次 |
| `requirements` | 本版本关联需求集合：标题、描述、优先级、来源、提出人（必填，至少 1 条） |
| `roadmap` | 产品路线图最新生效快照：项目认知、首期范围、三级清单（为空时降级） |
| `review_feedback` | 上一轮评审意见与结论（首次生成时为空） |

`requirements` 为空时**不得生成**，直接返回失败原因「本版本尚未关联需求」。

## 3. 生成流程（内部步骤）

1. 归纳需求：合并重复诉求，标注冲突项，形成版本目标。
2. 对齐路线图：把需求映射到「模块 / 功能点 / 操作项」，不在路线图中的新增项单独标注「规划外」。
3. 若有评审意见：逐条给出处理方式（采纳 / 部分采纳 / 不采纳 + 理由），并体现在正文变更说明中。
4. 渲染 PRD Markdown 与功能清单结构化数据两个产物。
5. 自检：需求覆盖、层级完整、操作项非空。

## 4. 输出契约（双产物）

### 4.1 PRD Markdown

严格按以下章节顺序输出，不得增删一级标题：

```markdown
# {项目名称} PRD-{版本号或「草稿」}

## 1. 版本概述
- 版本目标：
- 计划上线日：
- 关联需求数：
- 本版变更摘要：

## 2. 需求清单
| 需求 | 优先级 | 来源 | 说明 |

## 3. 功能详述
### 3.1 {模块}
#### {功能点}
- 功能描述：
- 操作项：
  - {操作项}：触发条件 / 主流程 / 异常分支
- 关联需求：

## 4. 交互与页面要求
- 页面入口、关键交互、状态与空态

## 5. 数据与接口要求
- 涉及的数据实体、字段、接口依赖

## 6. 非功能要求
- 性能、权限、兼容性、审计

## 7. 验收标准
- 可验证的验收条目（每条对应功能点或操作项）

## 8. 评审意见处理（重生成时必填）
| 意见 | 处理方式 | 说明 |
```

- 版本号未锁定时标题写「草稿」，不要自行编造 `X.Y.Z`。
- 正文只描述本版本范围；路线图后续规划项放入「版本概述」的变更摘要，不展开。

### 4.2 功能清单结构化数据（机器消费）

必须是单个 JSON 代码块，数组元素与 `pm_features` 一一对应：

```json
{
  "features": [
    {
      "module_name": "需求管理",
      "feature_name": "需求录入",
      "operation_name": "新建需求",
      "description": "一句话功能描述",
      "source": "prd",
      "status": "planned"
    }
  ]
}
```

约束：

- `source` 固定 `prd`，`status` 固定 `planned`。
- 三级路径必须与 PRD 第 3 章完全一致；同一功能点的每个操作项单独一条。
- 模块名 / 功能点名 / 操作项名不得为空，不得使用「其他」「待定」等占位词。
- 不得输出 `id`、`parent_id`、`project_id` 等由后端生成的字段。

## 5. 重生成规则

- 轮次递增：首次 `PRD`，之后 `PRD-v2`、`PRD-v3`，保留历史供对照。
- 重生成必须读取上一轮评审意见；未传入评审意见时，在输出开头标注「未检测到评审意见，按原需求重生成」。
- 已定稿版本不允许重生成；若上下文标记为已定稿，直接返回失败原因。

## 6. 沙箱能力边界

- **不得联网**：只使用注入的需求、路线图与评审意见。
- **单次执行不超过 120 秒**：需求较多时先输出功能清单 JSON，再输出 PRD 正文。
- **ReAct 不超过 10 轮**：不做多轮外部检索或自问自答。
- 只读上下文，不写库、不修改版本状态；落库与状态流转由调用方完成。

## 7. 失败兜底

| 情况 | 处理 |
|---|---|
| 无关联需求 | 返回 `{"error": "本版本尚未关联需求"}`，不生成空 PRD |
| 路线图缺失 | 按需求自行归纳模块，并在 PRD 开头标注「未关联路线图」 |
| 需求之间存在冲突 | 在「版本概述」列出冲突项与建议取舍，不擅自删除需求 |
| 功能清单 JSON 解析失败 | 仅重发 JSON 一次；仍失败则输出 Markdown 表格供调用方兜底解析 |
| 版本已定稿 | 返回 `{"error": "版本已定稿，不可重新生成"}` |
