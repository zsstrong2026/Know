# 会议室（Meeting Room）使用指南

会议室是 WeKnora 中的多智能体协作子系统：围绕一个主题创建"会议"，拉入多个智能体进行广播式讨论，用户逐条评审各智能体的意见，最终由主持人（系统）生成结构化方案，并沉淀为可回滚、可导出的产物。

## 1. 功能概述

- **广播式讨论**：用户发言后，参会智能体按顺序（sequential）或并行（parallel）模式依次发言，所有人可见全部发言。
- **主题澄清（grill-me 风格）**：创建会议后先由主持人输出开场分析；若主题过于宽泛（缺少目标、范围、时间、对象、评价标准等关键约束），主持人会列出 1~3 个编号问题并**附上推荐答案**，引导用户补充说明；用户补充后主持人收敛出一句话「主题简报」再进入讨论。澄清最多 1 轮。
- **会议聚焦**：讨论开始后，各智能体被约束「围绕主题作答、核心观点 ≤3 条、回应他人 ≤2 条且每条 ≤30 字并 @对方、无信息增量回 PASS」，抑制相互讨论中的发散与跑偏。
- **发言权路由**：由 `host-assign`（主持人指派）/ `mention`（提及驱动）/ `free`（自由抢麦）三种模式决定每轮由谁发言。
- **联网搜索（可选，会议级）**：开启后，参会智能体在检索知识库之外可联网搜索，并在回答中以引用形式标注网络来源；需先在系统设置中配置搜索引擎。
- **专家异构引导**：创建会议时，若所选智能体使用的模型相同，会提示为不同智能体配置不同模型，避免讨论观点同质化。
- **PASS 弃权**：智能体无信息增量时回 `PASS`，被静默跳过，不占用讨论产出。
- **用户评审**：每条智能体意见可标记"采纳 / 不采纳"，未处理的保持"待评审"。
- **主持人生成方案**：主持人汇总所有已采纳意见与被否决意见，生成包含「背景与目标 / 分歧与未达成一致的点 / 方案要点 / 风险与待确认事项 / 下一步行动」五小节的结构化方案（分歧节强制暴露未达成一致的点）。
- **裁判 + 共识检测（可选）**：开启后，每个讨论轮结束由独立裁判判定是否已收敛；收敛则落一条「共识」消息并结束讨论，避免无意义的空转。
- **产物管理**：每次生成方案都会产生带版本号的产物，支持查看历史、回滚到任意历史版本、导出为 Markdown 文件。
- **护栏机制**：两个智能体反复互相辩驳时，主持人自动打断并把话题拉回正题。

## 2. 核心概念

| 术语 | 说明 |
|---|---|
| 会议（Meeting Room） | 一个独立讨论空间，由创建者全权管理；**仅创建者可见** |
| 主持人（Host） | 系统自动担任的协调者，负责开场、澄清引导、打断互呛、生成方案；不可移除 |
| 参会智能体（Agent） | 创建会议时选择的 CustomAgent，至少 1 个；同一会议内不可重复 |
| 待确认（awaiting_confirmation） | 创建后、首轮讨论开始前的状态；用户点「开始会议」确认或直接发言后转 `active` |
| 主题简报（TopicBrief） | 主持人在澄清后收敛出的一句话会议主题；讨论时替代宽泛标题作为聚焦基准 |
| 联网总闸（WebSearchEnabled） | 会议级联网开关（创建时设定）；与智能体自身联网开关**同时为真**时，参会智能体才可联网检索 |
| 评审状态 | `pending`（待评审）→ `adopted`（采纳）/ `rejected`（不采纳）；采纳后可回设为待评审 |
| 方案（Solution） | 主持人基于已采纳意见生成的 `is_solution` 消息，带版本号 |
| 产物（Artifact） | 方案的版本化记录，含采纳/不采纳数快照，支持导出 |
| 护栏（Guard） | 互呛检测：同一对智能体在无用户介入的情况下连续互答达到阈值即打断 |
| 讨论轮（Turn） | 一次"用户发言触发 → 智能体依次应答 → 轮次结束"的完整过程；同一会议同一时刻最多一轮 |
| 发言权路由模式 | 决定每轮谁发言的策略：`host-assign` 主持人指派 / `mention` 提及驱动 / `free` 自由抢麦 |
| 主持人介入间隔 | 主持人每 N 个子轮做一次「阶段总结 + 重定向」，防止讨论跑偏；`0` 表示全程不介入（默认） |
| 弃权（PASS） | 智能体无信息增量时回复 `PASS`，该回复被静默丢弃，不计入讨论产出 |
| 共识检测 | 每轮结束由独立裁判智能体判定讨论是否已收敛；开启后会提前终止讨论 |
| 共识消息 | 裁判判定收敛后落库的 `is_consensus` 主持人消息，作为本轮讨论的收敛结论 |

## 3. 快速上手

1. **创建会议**：侧边栏进入「会议室」→「创建会议」，填写标题与描述，选择 1~N 个智能体，选择讨论模式与发言权路由模式；如需联网可按需开启「网络搜索」开关。
2. **开场与澄清**：进入会议房间后，主持人自动生成开场分析。若主题较宽泛，主持人会在「需要澄清的问题」小节列出 1~3 个问题（附推荐答案），此时输入框提示「主题澄清」，在下方补充说明关键约束即可；也可点「调整流程」补充修改意见，或直接点「开始会议」跳过澄清。
3. **开始讨论**：点「开始会议」确认后进入讨论，智能体将自动依次发言，SSE 实时推送；也可直接在输入框打字（隐式确认）开始。
4. **评审意见**：对每条智能体消息点击「采纳」或「不采纳」；可随时改判（回设为待评审）。
5. **生成方案**：确认采纳意见后点击「生成方案」，主持人输出结构化方案（需至少 1 条采纳意见）。
6. **导出方案**：右侧产物抽屉中查看历史方案，点击「导出 .md」下载 `meeting-solution-v{版本号}.md`。

## 4. 讨论模式与护栏

### 讨论模式

| 模式 | 语义 | 适用场景 |
|---|---|---|
| `sequential`（顺序，默认） | 智能体逐个发言，后者可见前者的发言，可相互呼应 | 需要观点交锋与迭代的深度讨论 |
| `parallel`（并行） | 智能体同时独立作答，互不感知 | 需要多视角独立意见的快速收集 |

- 会议级默认值由 `MEETING_DEFAULT_BROADCAST_MODE` 配置；创建会议时可指定，也可在会议详情中修改（PATCH）。

### 发言权路由

| 模式 | 语义 | 适用场景 |
|---|---|---|
| `host-assign`（主持人指派，默认） | 消息显式 @ 时优先响应被 @ 者；否则由主持人 LLM 按相关性指派；均无果则全员兜底 | 主题宽泛、需要主持人控场的讨论 |
| `mention`（提及驱动） | 仅被 @ 的智能体发言；无人被 @ 时由主持人指派兜底，避免冷场 | 用户想精确点名、控制发言范围的讨论 |
| `free`（自由抢麦） | 不筛选，全员发言 | 需要穷尽多视角、广撒网的讨论 |

- 路由模式在创建会议时指定，也可通过 PATCH 更新（`routing_mode`，白名单 `host-assign` / `mention` / `free`）；历史数据与非法值一律回退为 `host-assign`。

### 主持人每 N 轮介入

- 语义：主持人**不是每轮都发言**，而是每完成 N 个子轮（同一轮内智能体的一来一回算作一个子轮）由主持人插入一条「阶段总结 + 重定向」消息，概括已形成的共识与尚存的分歧、指出偏离主题之处，并把讨论重新聚焦回主题。
- 配置：创建会议时指定，也可通过 PATCH 更新（`host_every_n_rounds`，取值 `0` 或 `1..10`）。`0` 表示关闭（默认，主持人仅在开场、护栏打断、打断收尾、生成方案时发言）；超范围值一律按关闭处理。
- 触发条件：仅当**讨论仍会继续**（后续还有待发言的智能体）时才介入，避免讨论自然终止时插入无意义总结。
- 降级：主持人模型不可用或生成失败时，使用固定文案兜底，讨论不中断。
- 与护栏协同：主持人介入消息属于「非智能体消息」，会截断护栏的观察尾巴，因此介入本身有助于抑制互呛误判。
- 异构引导：会议内不同智能体可绑定不同模型（避免观点同质化），主持人也可使用独立模型；创建弹窗在选择同质模型时给出提示。

### 裁判 + 共识检测

- 语义：每个子轮结束后，交由一个**独立裁判智能体**判定本轮讨论是否已收敛（各方意见已趋于一致、无需继续辩论）。收敛则落一条带 `is_consensus` 标记的「共识」消息并**终止当前讨论轮**；未收敛则继续下一子轮。
- 配置：创建会议时指定，也可通过 PATCH 更新（`consensus_detection_enabled`，布尔，默认 `false`）。
- 裁判判定：复用主持人模型通道（`resolveHostChat`），以 `temperature=0` 输出 JSON `{"converged":bool,"reason":str,"consensus":str}`；`consensus` 字段即共识消息正文，缺省时回退为「讨论已收敛：{reason}」。
- 与主持人介入协同：裁判判定优先于主持人每 N 轮介入——一旦判定收敛即直接结束讨论，不再插入阶段总结。
- **fail-safe**：裁判模型不可用、调用失败或输出无法解析时，一律视为「未收敛」，讨论继续，绝不因裁判异常而中断。
- 前端表现：收到 `consensus.created` 事件时结束「讨论中」状态并展示共识提示条；共识消息以成功色气泡 + 「共识」标签渲染，可继续追问或直接生成方案。

### 护栏（互呛打断）

- 判定：最后一条用户/主持人消息之后，若**同一对智能体**严格交替发言且完整来回数 ≥ `guard_max_exchange`（默认 3），触发打断。
- 触发后：主持人发送护栏消息，把话题拉回用户最初议题；`guard.triggered` 事件广播到前端。
- 阈值可按会议调整（PATCH 的 `guard_max_exchange`，最小 1）；全局默认由 `MEETING_GUARD_MAX_EXCHANGE` 配置。

### 其他保护

- **打断讨论**：讨论进行中可点击「打断」，当前轮次尽快终止。
- **历史窗口**：构造 LLM 上下文时最多携带最近 `MEETING_CONTEXT_MAX_MESSAGES`（默认 50）条消息；更早的内容按需摘要压缩。
- **并发控制**：同一会议同一时刻仅允许一个讨论轮（Redis 分布式锁保证），重复触发不会叠加。

## 5. 主题澄清、会议聚焦与联网搜索

### 主题澄清（开场引导）

- **时机**：会议创建后处于 `awaiting_confirmation` 待确认状态，主持人先生成开场消息，其中包含「主题分析 / 需要澄清的问题 / 建议流程」三部分。
- **触发条件**：仅当主题**过于宽泛、缺少关键约束**（目标、范围、时间、对象、评价标准等）时，主持人才会输出「需要澄清的问题」小节，用 `<need_clarification>` 标记包裹 1~3 个编号问题，每个问题附主持人的推荐答案（形如「1. 问题？推荐：xxx」）。
- **用户动作**：处于澄清态时，输入框提示「主题澄清模式」，用户在输入框补充说明即可——该内容作为「补充说明」交给主持人，主持人结合意见重出开场并**收敛出一句话主题简报（TopicBrief）**，随后回到待确认态；用户也可直接点「开始会议」跳过澄清。
- **硬约束**：澄清**最多 1 轮**。非首次（用户调整流程或回答澄清后）重出的开场不再追问，直接给出收敛结论。
- **落库与展示**：标记 token（`<need_clarification>` / `<topic_brief>`）在后端**剥离后再落库**，前端展示的正文不含标记；开场消息的 `payload` 携带 `stage` 与 `needs_clarification`，前端据此渲染澄清提示与输入占位文案。
- **降级**：主持人模型不可用或开场生成失败时，落一条 system 兜底消息「主持人开场生成失败，可直接发言开始会议」，房间保持待确认，用户可直接发言隐式开跑。

### 会议聚焦约束

讨论开始后，为抑制智能体在相互讨论中逐渐偏离主题，引擎对**每一轮发言**同时施加两层约束：

- **系统提示词层**：为参会智能体的自定义系统提示词追加「会议聚焦要求」（围绕主题、核心观点 ≤3 条、回应他人 ≤2 条且每条 ≤30 字并 @对方、无增量回 PASS）。仅在智能体本身已解析出自定义系统提示词时追加，避免凭空设置反而替换掉平台默认提示词。
- **查询层**：构造单轮 query 时，以 `TopicBrief`（若已收敛）替代宽泛标题作为【会议主题】，并在末尾追加聚焦软约束若干条。

### 联网搜索（会议级）

- **配置**：创建会议时的「网络搜索」开关（`web_search_enabled`）。**仅创建时可设**，创建后不可通过 PATCH 修改。
- **生效条件**：会议级开关与参会智能体自身的联网开关**同时为真**时，该智能体的联网工具才会注册（`AgentQA` 侧为合取逻辑）；两者任一关闭则联网不生效。
- **来源标注**：联网检索到的内容以引用（citation）形式在回答中标注来源；前端会议消息复用统一 Markdown 渲染，网络来源以引用 chip 展示。
- **前置依赖**：需先在「系统设置」中完成搜索引擎的选择与接口配置；未配置时联网不会返回结果。会议创建弹窗对该开关常驻提示「需先在系统设置中配置搜索服务」。

## 6. 归档与删除

- **归档**：会议详情页点击「归档」。归档后会议进入**只读**状态——发言、评审、生成方案、回滚均被拒绝（返回 403「会议已归档，仅可查看」），但**历史浏览与方案导出不受影响**。列表页可通过「全部 / 进行中 / 已归档」筛选。重复归档幂等（仍返回成功，不产生重复系统消息）。
- **删除**：列表页点击「删除」并确认。删除为**软删除**，会议从列表消失、详情返回 404，数据保留在库中（`deleted_at` 非空）以便审计恢复。

## 7. API 一览

- `Viewer`：租户内任意成员（列表结果按创建者过滤，仅返回本人会议）
- `OwnedOrAdmin`：会议创建者本人或租户管理员

## 8. SSE 事件

订阅 `GET /api/v1/meetings/:id/stream`，响应为 `text/event-stream`，每条事件格式：

```json
{ "type": "<事件名>", "data": { ... } }
```

| 事件名 | 触发时机 | data 内容 |
|---|---|---|
| `message.created` | 新消息落库（用户/智能体/主持人/系统） | 消息对象（含 sender、content、review_state、payload 等） |
| `message.review_updated` | 评审状态变更 | 消息对象（含最新 review_state） |
| `discussion.turn_started` | 讨论轮开始 | 轮次上下文（触发消息等） |
| `discussion.turn_ended` | 讨论轮结束 | 轮次收尾信息 |
| `discussion.flow_confirmation` | 主持人生成开场消息（待确认流程） | `room_id` / `message_id` / `stage` |
| `guard.triggered` | 互呛护栏触发或被用户打断收尾 | 主持人护栏消息与互呛双方（或 `reason=user_interrupt`） |
| `consensus.created` | 裁判判定讨论收敛 | `room_id` / 共识消息对象 / 收敛原因 / 已完成子轮数 |
| `solution.generating` | 方案生成开始 | 提示性事件（前端显示生成中状态） |
| `solution.created` | 方案生成完成 | 方案消息对象（含版本号） |
| `artifact.generating` | 产物生成开始 | `room_id` / 产物标识（前端显示生成中） |
| `artifact.created` | 产物生成完成 | 产物对象（含正文、版本号、统计快照） |
| `artifact.failed` | 产物生成失败 | `room_id` / 产物标识 / 失败原因 |
| `ping` | 心跳保活 | 空 |

**断线重连**：前端使用 `@microsoft/fetch-event-source` 订阅，断线后自动重连；重连后通过 `GET /messages` 拉取历史补齐缺口，事件流本身不回放。

## 9. 配置项

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `MEETING_GUARD_MAX_EXCHANGE` | `3` | 全局互呛护栏阈值（完整来回数）；会议可单独覆盖 |
| `MEETING_CONTEXT_MAX_MESSAGES` | `50` | 构造 LLM 上下文时携带的最近消息条数上限 |
| `MEETING_DEFAULT_BROADCAST_MODE` | `sequential` | 新建会议的默认讨论模式 |

以上均可通过环境变量覆盖，未配置时使用默认值；非法值（≤0 / 非法模式）自动回退默认。

## 10. FAQ

**Q：归档后还能导出方案吗？**
能。归档仅冻结"写操作"（发言/评审/生成/回滚），历史浏览与 `导出 .md` 不受影响。

**Q：为什么我看不到同事创建的会议？**
会议室遵循"仅创建者可见"：列表与详情均按 `tenant_id + created_by` 双重过滤，其他人（含同租户）访问返回 404。租户管理员经由管理通道可见。

**Q：主题写得太宽泛，智能体还是会自由发挥怎么办？**
主持人会在开场时先做主题分析，主题宽泛时列出 1~3 个问题（附推荐答案）引导你补充关键约束（目标/范围/时间/对象/评价标准），收敛出一句话主题简报后再开始讨论；讨论中智能体还会被要求「围绕主题、观点 ≤3 条、回应从简、无增量回 PASS」。补充说明后若仍偏题，可用「调整流程」再次收敛，或把「主持人介入」设为每 N 轮。

**Q：澄清问题不想回答，能跳过吗？**
可以。处于主题澄清态时，直接点「开始会议」即可跳过澄清、立即进入讨论；此前对话也会作为背景保留。

**Q：怎么让智能体联网搜索？**
在「创建会议」时打开「网络搜索」开关（会议创建后不可再改）。开启后参会智能体会在检索知识库之外联网搜索并标注来源。注意：该开关需与智能体自身的联网开关同时开启才生效，且需先在「系统设置」中完成搜索引擎的选择与接口配置；未配置时联网不会返回结果。

**Q：方案生成为什么报"没有已采纳的意见"？**
生成方案要求至少 1 条 `adopted` 状态的智能体消息，请先评审采纳；`rejected` 与 `pending` 均不参与。

**Q：方案生成错了怎么办？**
每次生成都是新版本，不会覆盖旧版。在产物抽屉中选择历史版本「回滚」即可把当前方案指针切回去；回滚本身也可再次操作（指向任意历史版本）。

**Q：两个智能体互相抬杠停不下来？**
护栏会在达到阈值（默认 3 个来回）时由主持人自动打断；也可以手动「打断讨论」，或调低该会议的护栏阈值。

**Q：开启共识检测后讨论提前结束了？**
这是预期行为：裁判判定已收敛即落一条「共识」消息并结束本轮讨论。可在该消息后继续追问，或直接「生成方案」。裁判不可用或判定失败时不会提前结束。

**Q：智能体的意见看起来差不多，怎么办？**
检查参会智能体是否绑定了同一模型（或都跟随默认模型）——创建会议时会给出同质提示。为不同智能体（如法务、架构、产品）分别配置不同模型，可显著降低观点同质化。

**Q：讨论跑偏了／绕圈了怎么办？**
可在创建或修改会议时把「主持人介入」设为每 N 轮（1~10），主持人会在每完成 N 个子轮后插入一条阶段总结并把话题拉回主题；设「不介入」（`0`）则全程由智能体自行推进。讨论自然结束前不会插入多余总结。
