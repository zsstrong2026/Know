# 文档助手（doc-assistant）设计

> 状态：待实施 · 范围：前后端 · 更新时间：2026-09-27

## 1. 目的

让内部专业人员**借助知识库内容 + 可维护的文档模板，按自定义主题输出结构化长文档**。

典型场景：知识库中沉淀了产品资料与最佳实践，用户选择「周报」「活动策划方案」等模板，勾选相关知识库作为素材池，输入主题「Q3 产品周报」和补充要求，系统按模板的章节骨架逐章检索素材并生成一篇可导出 Word 的完整文档。

## 2. 非目标（本版明确不做）

- PDF 导出（只做 Markdown + Word）
- 句级角标引用（只做章节级参考资料）
- 模板租户共享 / 协作编辑（模板仅创建者私有）
- 骨架结构编辑：生成后不可增删章节、不可改章节顺序（只可编辑章节文字内容）
- 流式输出（同步打字机）
- 模板分类与搜索
- 生成结果回存知识库（v1 不做闭环，文档只落 `.local-data` 供预览/导出）

## 3. 关键决策记录

| 维度 | 决策 |
|------|------|
| 目标用户 | 内部专业人员 |
| 产出物 | 结构化长文档，交付 **Markdown + Word (DOCX)** |
| 素材范围 | 知识库为素材池（可勾选多库 + 可选过滤条件），生成时按主题**动态语义检索** top-k chunk |
| 模板形态 | **章节骨架**：模板 = 章节列表（标题 / 生成指令 / 篇幅 / 开关）+ 全局设定；**个人私有**维护 |
| 生成交互 | **异步任务 + 历史记录**（查看 / 导出 / 重新生成 / 删除） |
| 生成策略 | **逐章生成**：每章独立"检索 → 生成 → 附参考资料"；单章失败可重试；模型**由用户在生成时选择**（默认平台默认模型） |
| 引用溯源 | **每章末尾附参考资料**（来源文档名，可跳转原文） |
| 生成入口 | 主题（必填）+ 可选补充要求（自然语言，注入每章） |
| 章节编辑 | **仅编辑章节文字内容**，版本化生成（原版可回退） |
| 素材不足 | 每章「必须引用素材」开关：开 → 素材不足则跳过并标注；关 → 允许基于通用知识生成并标注 |
| 权限/隔离 | 模板、任务、文档均按 owner 隔离（租户内个人私有） |
| 模块定位 | **独立模块**，复用 knowledge-search 检索 + 现有 LLM 调用器，不新建一套生成系统 |

## 4. 复用与新建

本功能**不是**新建一套检索/生成系统，而是在现有平台上新增一个独立功能模块。复用关系：

| 能力 | 复用来源 |
|------|----------|
| 跨库检索 | `POST /api/v1/knowledge-search` 的 service 层调用（支持 `knowledge_base_ids` / `knowledge_ids`），返回 chunk `content` / `knowledge_title` / `knowledge_filename` / `score` |
| 素材范围过滤 | `KnowledgeListFilter`（tags / keyword / fileType / parseStatus / source / 时间 / 文件夹路径，见 `internal/types/knowledge.go`） |
| LLM 非对话调用 | `modelService.GetChatModel(ctx, modelID)` → `chat.Chat`；prompt 组装参考 `internal/application/service/knowledge_process.go`（`RenderPromptPlaceholders` + `WithLLMCallMetadata` + `chat.ChatOptions`，摘要/问题生成同款模式） |
| 异步任务 | Lite 模式 `SyncTaskExecutor`（`internal/router/sync_task.go`）；标准模式 asynq + `internal/router/task.go`（`mux.HandleFunc`）。新增一个任务类型 `TypeDocumentGenerate`，两处同时注册 |
| 存储 | PostgreSQL（模板 / 任务 / 文档 / 版本表）+ `.local-data`（导出的 md 文件） |
| 前端页面骨架 | 现有导航 + API client + i18n 模式（参照知识库/FAQ 页面） |

新建部分：

- 后端 `internal/application/service/doc_assistant/`（模板 CRUD、生成任务编排、逐章生成、导出）
- `internal/handler/doc_assistant.go`（API 层）
- 三张数据表 + 对应 repository
- 前端「文档助手」导航入口及 4 个页面

## 5. 核心流程

```
文档助手首页
  ├─ 模板管理（个人私有）：新建/编辑模板（章节骨架） → 保存
  └─ 生成文档：
      1. 选模板 → 选素材知识库（多选 + 可选过滤） → 选模型 → 填主题 + 可选补充要求
      2. 提交 → 创建 doc_generation_tasks（status=pending）→ 入队 asynq/SyncTaskExecutor
      3. 后台执行：逐章
         检索 query = 主题 + 补充要求 + 章节标题/指令 → knowledge-search(kb_ids, top_k)
         素材不足判定 → 按章节开关 跳过 或 降级生成
         prompt = 全局上下文 + 检索片段(按知识归并截断) + 章节指令 → chat.Chat
         产出该章 content + references（按来源知识去重归集）
      4. 全部完成 → status=success / partial_success → 章节内容落库，md 文件落 .local-data
      5. 历史列表：查看 / 单章编辑续写(新版本) / 重新生成 / 导出 Word / 删除
```

## 6. 模板模型

模板为章节骨架，存 JSON。字段草案：

| 层级 | 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| 模板 | `name` | string | 是 | 模板名称 |
| 模板 | `description` | string | 否 | 适用场景说明 |
| 模板 | `global_config` | object | 否 | 默认语气 / 目标读者 / 默认补充要求（可被生成时覆盖） |
| 模板 | `chapters` | array | 是（至少 1） | 章节列表 |
| 章节 | `title` | string | 是 | 章节标题（同时作为生成的 md 标题） |
| 章节 | `instruction` | string | 否 | 该章生成指令（写什么、侧重什么） |
| 章节 | `max_words` | int | 否 | 期望篇幅上限，夹紧到 [200, 5000] |
| 章节 | `must_reference` | bool | 否（默认 true） | 必须引用素材开关 |
| 章节 | `skippable` | bool | 否（默认 false） | 素材不足时是否可跳过（仅对 must_reference=false 章节生效时用于标注） |

校验规则：

- `chapters` 为空 → 创建/更新失败（`ErrInvalidConfig`）。
- 章节数上限 30，超出只取前 30 个并日志提示，不报错。
- 数值字段越界 → 夹紧到上限并日志提示（与数据源连接器行为一致，避免用户改模板即失败）。

## 7. 生成任务行为规范

### 7.1 逐章检索

- 检索 query 构造：`主题 + 补充要求 + 章节标题 + 章节 instruction`（拼接为一段检索文本），复用 knowledge-search service（`knowledge_base_ids` 传用户勾选的库；可选附加 `KnowledgeListFilter` 过滤）。
- `top_k` 默认 8，模板 global_config 可设，任务创建时可覆盖，上限 20。
- 命中片段按来源知识归并，供生成与"参考资料"共用。

### 7.2 素材不足

| 情况 | 行为 |
|------|------|
| 无命中或命中片段内容过短，且 `must_reference=true` | 该章标记 `skipped`，文档内标注「素材不足，本章未生成」，任务仍继续 |
| 无命中，且 `must_reference=false` | 降级：基于通用知识生成，章节末尾标注「本章基于通用知识，未引用知识库」 |
| 全部章节均 `skipped` | 任务结束，`status=failed`，error 提示「所选知识库无相关素材」 |

### 7.3 每章生成

- prompt 结构：系统指令（角色 + 全局上下文：主题、补充要求、模板 global_config、已生成章节标题列表以保证连贯）+ 用户内容（章节标题、instruction、检索片段；片段过长用 `[...内容省略...]` 截断，与现有摘要生成一致）。
- 模型：`GetChatModel(ctx, modelID)`，modelID 来自任务创建时用户选择。
- 输出：该章正文（Markdown）+ `references`（按来源知识去重：`knowledge_id` / `knowledge_title` / `knowledge_filename` / 用到的 `chunk_ids`）。

### 7.4 单章失败与重试

- 单章生成失败（LLM 错误/超时）→ 该章标记 `failed`，任务继续其余章节；全部完成后任务 `status=partial_success`，历史列表提示「N 章失败」。
- 用户可对失败章节发起「重新生成该章」（`POST .../documents/:id/versions/:version/chapters/:no/regenerate`），生成新版本。
- 任务级 asynq 重试语义：handler 以"从失败章节续跑"实现幂等（每章完成即写库 checkpoint），避免重跑已成功章节浪费 LLM 配额。

### 7.5 版本化

- 一次「生成」产生文档 **v1**；「单章编辑续写」或「重新生成单章」→ 复制前版生成 **v+1**（仅替换该章内容与引用），历史可回退查看旧版。
- 「重新生成」（整篇）→ 创建**新任务**（沿用模板/素材/模型/主题参数），历史列表出现新条目。
- 生成后编辑只允许改章节文字内容；改完保存即为新版本（`edited` 标记）。

### 7.6 Word 导出

- **导出均为动态生成**：Markdown 与 docx 都由导出接口在请求时根据文档最新章节内容实时渲染并流式返回（`Content-Disposition: attachment`），不落盘、不依赖存储后端；`doc_documents.md_path` 字段保留（可空）供后续扩展。
- 转换选型：**纯 Go**（goldmark 语义的行级解析 + 手写 docx XML 打包），不引入 pandoc 等外部二进制——与 Lite 单文件分发契合。
- 已知局限：v1 仅支持标题/段落/列表与加粗/斜体；表格等复杂元素先降级为段落文本（列入后续增强）。

## 8. 数据模型

沿用 PostgreSQL 模式，新增三张表（`internal/repository/` 对应实现 + 建表迁移）：

### `doc_templates`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | uuid | PK |
| `owner_id` | uuid | 创建者（个人私有隔离） |
| `tenant_id` | uuid | 租户 |
| `name` / `description` | text | 名称 / 说明 |
| `global_config` | jsonb | 默认语气 / 目标读者 / 默认补充要求 / 默认 top_k |
| `chapters` | jsonb | 章节骨架数组 |
| `created_at` / `updated_at` | timestamptz | 时间戳 |

### `doc_generation_tasks`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | uuid | PK |
| `owner_id` / `tenant_id` | uuid | 归属 |
| `template_id` | uuid | 使用的模板（快照外键，模板删除不影响历史） |
| `template_snapshot` | jsonb | 生成时的模板快照（模板被改后历史可还原当时的骨架） |
| `kb_ids` | jsonb | 素材知识库列表 |
| `kb_filters` | jsonb | 可选过滤条件（KnowledgeListFilter） |
| `model_id` | string | 用户选择的模型 |
| `theme` | text | 主题（必填） |
| `extra_requirement` | text | 补充要求（可空） |
| `status` | text | pending / running / success / partial_success / failed / cancelled |
| `progress` | jsonb | 各章节状态（pending/retrieving/generating/done/failed/skipped） |
| `error` | text | 任务级错误 |
| `created_at` / `finished_at` | timestamptz | 时间戳 |

### `doc_documents`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | uuid | PK |
| `task_id` | uuid | 来源任务 |
| `version` | int | 版本号，v1 起 |
| `status` | text | generated / edited |
| `chapters` | jsonb | `[{no, title, content, references:[{knowledge_id, title, filename, chunk_ids}]}]` |
| `md_path` | text | `.local-data` 下的 md 文件路径 |
| `created_at` | timestamptz | 时间戳 |

> 模板删除 → 软删，历史任务/文档保留（引用 `template_snapshot`）。

## 10. 错误处理与重试

- 单章失败 → 不中断，任务收尾为 `partial_success`，失败章可单独重生成。
- 素材不足 → 按章节开关跳过/降级（见 7.2），不产生任务级错误。
- 检索失败（KB 已删/无权限）→ 该章 `failed`；全部失败且无产出 → 任务 `failed`，error 含具体原因。
- 任务 handler 幂等：每章完成即落库 checkpoint；asynq/SyncTaskExecutor 重试时从第一个未完成章节续跑。
- 导出 Word 失败 → 接口返回错误，可重试；md 文件始终保留为兜底交付物。

## 11. 测试方案

单元测试（service 层，注入 fake 检索 / fake chat，参照 `knowledge_summary_reconstruction_test.go` 的 fake 模式）：

| 用例 | 断言 |
|------|------|
| 模板 CRUD | 建/改/删/查，章节校验（空 chapters 拒绝、数量与数值夹紧）、owner 隔离 |
| 逐章生成 | 每章调用检索（query 含主题+章节）、命中片段进 prompt、产出 content + references |
| 引用归并 | 同一来源知识多个 chunk → references 只出现一次，chunk_ids 合并 |
| 素材不足-跳过 | `must_reference=true` 无命中 → 章 skipped，任务 success 且文档标注 |
| 素材不足-降级 | `must_reference=false` 无命中 → 生成且标注"未引用知识库" |
| 全部 skipped | 任务 failed 且提示无素材 |
| 单章失败 | 一章失败其余成功 → partial_success；重生成该章后新版本只替换该章 |
| 版本化 | 单章续写 → version+1，其余章内容不变 |
| checkpoint 续跑 | 模拟任务重试，已成功章节不重复调用 LLM |
| 导出 | md 文件落盘；md→docx 冒烟（标题/段落/列表可见） |

回归：`go test ./internal/application/service/... ./internal/handler/... ./internal/router/... ./internal/types/...`，确认新增任务类型注册未破坏既有任务分发测试。

## 12. 验收标准

1. 通过 API 创建模板（章节骨架），个人私有：他人无法读到/修改。
2. `POST /api/v1/doc-assistant/generate`（选库 + 选模型 + 主题）→ 任务异步执行 → 状态经 pending/running 到 success；各章内容基于知识库素材生成，每章末尾有参考资料。
3. 素材不足章节：按开关分别呈现"跳过标注"与"通用知识标注"；全部无素材时任务失败并给出提示。
4. 历史列表：查看 / 删除 生效；单章编辑续写产生新版本且可回退旧版；「重新生成」产生新任务条目。
5. 导出 Word 成功，章节标题映射为 Word 标题样式，可正常打开。
6. 单章生成失败 → partial_success，对该章「重新生成该章」成功且不影响其它章。
7. 现有既有测试全部通过（无误伤）。
