# 主题网络搜索数据源（topic_search）设计

> 状态：后端已实施（前端待做）· 范围：仅后端 · 更新时间：2026-09-25

## 1. 目的

让用户为某个知识库配置一个**自定义主题**，系统按**定时任务**在公网搜索该主题的相关文档，抓取网页正文、下载解析并入库。用户无需手工维护 URL 清单。

典型场景：为"大模型 RAG 最新进展"知识库配置主题 `RAG 检索增强生成`，每天 08:00 自动把公网新出现的相关文章收进知识库。

## 2. 非目标（本版明确不做）

- 前端 UI（第二阶段）
- LLM 相关度过滤 / 自动摘要
- PDF、Word 等文件直链下载（只处理网页正文）
- 每个主题独立的抓取频率（同一数据源共用一条 cron 表达式）
- 删除同步：网页从搜索结果中消失**不会**删除知识库中已入库的文档
- 抓取失败时用搜索摘要兜底（失败即记录，不写入低质内容）

## 3. 复用与新建

本功能**不是**新建一套定时任务系统，而是在现有"数据源同步"框架上新增一种连接器。复用关系如下：

| 能力 | 复用来源 |
|------|----------|
| cron 定时、防重叠、多实例去重 | `internal/datasource/scheduler.go` |
| 异步执行、重试、超时 | asynq 任务 `TypeDataSourceSync` |
| 增量游标持久化 | `DataSource.LastSyncCursor` / `types.SyncCursor` |
| 同步日志、手动同步、暂停/恢复、权限 | `DataSourceService` / `/api/v1/datasource` |
| 入库并触发解析 | `DataSourceService.ingestItem` → `CreateKnowledgeFromFile` |
| 公网搜索 | `interfaces.WebSearchService`（11 种 Provider，租户级配置） |
| 网页抓取（SSRF 安全 + HTML→正文） | `internal/infrastructure/web_fetch.Fetcher` |

新建部分：一个连接器 `internal/datasource/connector/topicsearch/`。

## 4. 数据流

```
现有 cron 调度器（每个数据源一条 cron）
  → asynq 任务 TypeDataSourceSync → DataSourceService.ProcessSync
  → topicsearch 连接器 FetchIncremental / FetchAll：
      1. 读取主题列表（Settings.topics）
      2. 解析搜索 Provider（Settings.provider_id，留空则取租户默认）
      3. WebSearchService.Search(主题) → 搜索结果（含 URL、标题、发布时间）
      4. 与游标比对：URL 未变 → 跳过；URL 新增或正文变化 → 抓取
      5. web_fetch.Fetcher 抓取网页正文（SSRF 安全，失败退回 Chromium 渲染）
      6. 产出 FetchedItem（ExternalID = 规范化 URL，Content = 正文）
  → 现有 ingestItem：external_id 命中则删除重建（记为 updated），否则新建
  → CreateKnowledgeFromFile → 解析 / 分块 / 向量 / 索引（全复用）
```

## 5. 配置模型

配置存放于 `DataSourceConfig.Settings`（非密钥，走普通配置字段），`Credentials` 为空。

| 字段 | 类型 | 必填 | 默认 | 上限 | 说明 |
|------|------|------|------|------|------|
| `topics` | string | 是 | — | 20 个 | 主题关键词，多行或逗号分隔；每个主题是一个可选"资源" |
| `provider_id` | string | 否 | 租户默认 Provider | — | Web 搜索 Provider ID |
| `max_results_per_topic` | int | 否 | 10 | 50 | 每个主题取多少条搜索结果 |
| `max_items_per_run` | int | 否 | 5 | 50 | 单次同步最多产出多少篇（新增 + 更新合计） |
| `min_content_length` | int | 否 | 200 | — | 正文字符数下限，低于则跳过（不建文档，不计失败） |
| `result_recency_days` | int | 否 | 0（不限） | 365 | 只接收发布时间在 N 天内的结果；无发布时间的保留 |
| `blacklist` | string | 否 | 空 | — | 域名排除规则，多行；复用现有通配（`*://*.x.com/*`）与 regex（`/x\.(net|org)/`）格式 |

配置键说明：
- `topics` 为空 → 创建时校验失败（`Validate` 返回 `invalid config: topics is required`）。
- 主题数超过 20 → 只取前 20 个并在日志中提示，不报错；数值型字段越界 → 一律夹紧到上限并在日志中提示，不报错（避免用户改配置即同步失败）。
- `provider_id` 非空但不存在 → `Validate` 失败。留空时按**租户默认 Provider**（`WebSearchProviderRepository.GetDefault`）解析；无默认 Provider 则失败，提示"未配置默认 Web 搜索 Provider，请在设置中设为默认，或在本数据源指定 provider_id"。
- 搜索调用参数构造：`WebSearchConfig{ MaxResults: max_results_per_topic, Blacklist: <解析后的规则数组>, IncludeDate: result_recency_days > 0 }`；`IncludeDate` 仅在需要按时效过滤时打开，避免无谓的 Provider 参数变化。

连接器元数据（供 `/api/v1/datasource/types` 与前端展示）：

| 项 | 值 |
|----|----|
| `Type` | `topic_search` |
| `Name` | 主题网络搜索 |
| `Description` | 按自定义主题定时搜索公网并自动入库相关网页 |
| `AuthType` | `none` |
| `Capabilities` | `incremental` |
| `Priority` | 13 |

## 6. 连接器行为规范

实现 `datasource.Connector`；**不实现** `StreamingConnector`（单轮条目量小，无需断点续传）。

| 方法 | 契约 |
|------|------|
| `Type()` | 返回 `types.ConnectorTypeTopicSearch`（`"topic_search"`） |
| `Validate(ctx, config)` | ① 配置解析与范围校验；② 解析搜索 Provider（`provider_id` 或租户默认）；③ **实跑一次搜索**（取 1 条结果）验证 Provider 可用 |
| `ListResources(ctx, config, parentID)` | `parentID == ""` 时每个主题返回一个 `Resource`（`ExternalID` = 主题原文，`Type` = `topic`，`Name` = 主题）；`parentID != ""` 返回空 |
| `ResolveResourceAncestors(...)` | 返回空切片（扁平结构，与 RSS 一致） |
| `FetchIncremental(ctx, config, cursor)` | 增量：按游标判定，只产出新增或正文变化的条目；返回新游标 |
| `FetchAll(ctx, config, resourceIDs)` | 全量：忽略游标重新抓取，配额与正文下限仍生效 |

### 6.1 主题与资源

- `resourceIDs` 为空 → 同步全部主题；非空 → 只同步所选主题（值 = 主题原文）。
- 单轮遍历顺序：按 `topics` 配置顺序。

### 6.2 去重与更新语义

- `external_id` = **规范化 URL**：小写 scheme/host、去 fragment、去常见追踪参数（`utm_*`、`gclid`、`fbclid`、`msclkid`、`yclid`、`spm`、`scm`、`_ga`），保留 path 与业务 query（query 按 key 排序，保证同一页面得到同一个 key）。
- 游标结构：`{ "pages": { "<规范化URL>": { "signal": "<标题+摘要+发布时间的哈希>", "hash": "<正文 sha256>", "topic": "<主题>", "at": "<抓取时间 RFC3339>" } } }`，持久化于 `SyncCursor.ConnectorCursor`。
- **两级变更检测**（与 RSS 连接器同构）：
  1. `signal`（搜索结果可见字段：标题 + 摘要 + 发布时间）未变 → **不抓取**，直接跳过，零网络成本；
  2. `signal` 变了 → 抓取页面，比较正文 `hash`：相同则跳过，不同则产出（更新）。
  已知局限：页面正文变了但标题、摘要、发布时间都未变时，更新要等到搜索结果的摘要刷新后才会被发现（与 RSS 连接器的已知局限一致）。
- 判定规则：

| 情况 | 行为 | 同步日志计数 |
|------|------|--------------|
| URL 不在游标 | 抓取并产出 | created |
| URL 在游标，`signal` 与 `hash` 均未变 | 跳过，且**不抓取** | skipped |
| URL 在游标，`signal` 变但正文 `hash` 相同 | 抓取后跳过（更新游标 signal） | skipped |
| URL 在游标，正文 `hash` 不同 | 抓取并产出（服务层按 external_id 删除重建） | updated |
| 正文短于 `min_content_length` | 跳过，不产出（记录游标，避免下轮重复抓取） | skipped |
| 页面抓取失败 | 跳过，**不写游标**（下轮重试） | 记入错误样本（`SyncResult.Errors`，受现有 100 条上限保护） |
| 同一轮内多个主题命中的同一 URL | 只处理第一次出现 | skipped |

- 时效过滤：`result_recency_days > 0` 且搜索结果带发布时间且早于阈值 → 跳过（不抓取）；无发布时间的保留。
- 游标写入策略：把**本轮已成功抓取或已判定为稳定**的 URL 写入新游标；未处理（含因配额中断）的 URL 不写入，下轮仍视为新 URL。搜索失败的主题不写入任何条目。
- 黑名单（`blacklist`）通过 `WebSearchConfig.Blacklist` 交给 `WebSearchService` 过滤，连接器不重复实现过滤逻辑（避免两套规则漂移）。

### 6.3 配额

- `max_items_per_run` 统计本轮**产出**的条目数（created + updated），达到上限后立即停止抓取剩余结果，按搜索结果的相关性顺序优先。
- 已判定为 skipped 的条目**不占用**配额。

### 6.4 内容形态

- 使用 `web_fetch.NewFetcher()`：优先 HTTP 抓取，正文为空或疑似 JS 渲染页时退回 Chromium 渲染；运行环境无 Chromium 时自动退化为纯 HTTP 路径（不影响流程，仅这类页面会抓取失败）。
- 连接器只依赖一个单方法接口（`type pageFetcher interface { Fetch(ctx context.Context, rawURL string) (string, error) }`，由 `*web_fetch.Fetcher` 满足），便于单测注入假实现。
- 抓取结果为**纯文本**（HTML 已剥离标签与 script/style/nav/footer）。
- `FetchedItem.FileName` = `<净化后的标题>.md`（标题为空时用 URL 的 host + path 摘要）；`ContentType` = `text/markdown`；纯文本是合法 Markdown，与 RSS 连接器保持一致，且 `.md` 在支持导入的扩展名列表内。
- `FetchedItem.URL` = 原始 URL（保留搜索结果给出的形态，便于溯源）；`Title` = 搜索结果标题；`UpdatedAt` = 搜索结果发布时间（缺失则用抓取时间）。
- `FetchedItem.Metadata` 至少包含：`channel = "topic_search"`、`topic`、`source_url`、`search_provider`、`published_at`（有则填）。

## 8. 错误处理与同步日志

- 单个主题搜索失败 → 收集警告，继续其余主题；**全部主题失败且本轮无任何产出** → 返回错误（与 RSS 一致）。
- 部分主题失败或部分条目失败 → 返回 `datasource.PartialFetchError`，同步日志状态 `partial`，失败明细进 `SyncResult.Errors`。
- 抓取失败与正文过短不中断整轮同步。
- 抓取超时由 `Fetcher` 内置控制（单次调用 60s，HTTP 与渲染路径共用该超时）；单轮总时长受 asynq 任务超时（现有 2 小时）约束。

## 9. 测试方案

单元测试（`connector_test.go`，连接器只依赖接口，用 fake 注入搜索与抓取）：

| 用例 | 断言 |
|------|------|
| 新增 | 搜索结果中的新 URL 被产出，`ExternalID` 为规范化 URL，`FileName` 以 `.md` 结尾 |
| 未变跳过 | 游标已有同 URL 同 signal 同哈希 → 不产出，且**未调用抓取器** |
| 摘要变但正文未变 | signal 变、抓取后哈希相同 → 不产出，游标 signal 已更新 |
| 变化重抓 | 游标同 URL 不同哈希 → 产出 |
| 过短跳过 | 正文短于阈值 → 不产出，但仍写入游标 |
| 抓取失败不写游标 | 抓取报错 → 不产出，且游标中无该 URL（下轮可重试） |
| 配额截断 | 结果多于 `max_items_per_run` → 产出数等于上限，且游标只记录已处理项 |
| 黑名单传递 | 配置的 `blacklist` 原样出现在传给搜索服务的 `WebSearchConfig.Blacklist` 中（过滤由服务负责） |
| 时效过滤 | `result_recency_days` 内/外的条目分别保留/跳过；无发布时间者保留 |
| 主题部分失败 | 一个主题搜索失败、另一个成功 → 返回 `PartialFetchError` 且仍有产出 |
| 不可达搜索/默认 Provider 缺失 | `Validate` 与 fetch 均返回错误（含 `ErrInvalidConfig`） |
| 配置校验 | `topics` 为空 → `Validate` 返回 `ErrInvalidConfig` |
| 数值夹紧 | 超出上限的配置被夹紧而非报错 |
| URL 规范化 | 带 `utm_*`、fragment、大小写 host、query 顺序不同的同一页面归一为同一 `ExternalID` |
| 同轮跨主题去重 | 两个主题命中同一 URL 时只产出一次 |

回归：`go test ./internal/datasource/... ./internal/application/service/... ./internal/types/...`，确认租户上下文前置未破坏既有测试。

## 10. 验收标准

1. 通过 `POST /api/v1/datasource` 创建 `type = topic_search` 的数据源（`sync_schedule` 用现有 cron 表达式，如 `0 0 8 * * *`），`Validate` 能对不通的 Provider 报错。
2. `POST /api/v1/datasource/:id/sync` 手动触发后，知识库中出现与主题相关的网页文档，来源标识为 `topic_search`，解析状态最终为成功。
3. 立即再次触发同步：已入库且正文未变的页面不被重复入库，同步日志中体现为 skipped。
4. 修改某页面内容后重新触发：该文档被替换为新版本，日志体现为 updated。
5. 每轮产出条目数不超过 `max_items_per_run`；短于 `min_content_length` 的页面不入库。
6. 不配置 `provider_id` 时使用租户默认搜索 Provider；租户无任何 Provider 时创建校验失败并提示先配置 Provider。
7. 现有 16 种连接器的既有测试全部通过（无误伤）。

前端已完成：

- 「知识库设置 → 数据源 → 新建」的类型卡片新增「主题网络搜索」（`DataSourceEditorDialog.vue` 的本地 `connectorDefs` 增加 `topic_search` 条目）。
